LeetCode Coach

React, TypeScript, Hono, PostgreSQL

Source Live app may take about a minute to wake

A deployed, offline-first web app for interview prep: it plans what to practise each day, schedules reviews with the FSRS spaced-repetition algorithm — checked against the reference implementation on hundreds of random review histories — and runs timed mock interviews whose spoken explanations Claude scores against a five-point rubric.

Banking Transactions API

Java 21, Spring Boot 3, PostgreSQL

Source

A core banking service: accounts, deposits and withdrawals that reject overdrafts, and transfers that either commit on both legs or roll back entirely.

Concurrent transfers take row locks in ascending account-id order, which rules out both double-spend and deadlock; a CI test fires 100 opposite transfers at once against a real PostgreSQL and checks that no money is created. An Idempotency-Key header means a client that times out and retries cannot pay twice.

Every balance movement writes an immutable ledger row, and five SQL reconciliation queries — a window-function running total, paired transfer legs, conservation of money — return the rows that break a rule. Each check is proven by a test that corrupts one row and expects it to be caught. 32 tests run in GitHub Actions on every push.

Job-Opening Monitor

Node.js, TypeScript, Supabase

Source

A scheduled pipeline that reads more than 22,000 postings per run from over 110 sources — Workday, Greenhouse, Lever, Ashby, SmartRecruiters and others — and normalizes them behind one adapter layer, with bounded-concurrency fetches and one failing source never taking down the run.

A Postgres state table makes re-runs idempotent, so nothing ever alerts twice. Each run reports per-source health — p95 latency and whether a failure was DNS, timeout, rate limit, HTTP, or parsing. A language-model screening stage fails closed: when its API credit ran out, it held results back instead of letting unscreened ones through. Over 340 Vitest tests.

quantlab

Python, pandas, NumPy

Source

A backtesting and research engine for equities, crypto, and prediction markets. Every signal fills on the next bar, so a strategy cannot trade on information it would not have had at the time. Fees and slippage are charged on turnover, and every result is scored against simply holding the asset — a strategy that cannot beat holding is not a strategy.

Seven strategies sit behind one interface, and a registry discovers new ones automatically, so adding a strategy requires no change to the engine. Anchored walk-forward validation reports in-sample against out-of-sample Sharpe for each fold, which is the quickest way to see that a parameter set was fitted rather than found.

Credit Card Default Risk

Python, SQL, XGBoost, SHAP, Tableau

Source Dashboard

Portfolio risk analysis across 30,000 credit card customers. Five SQL analyses using window functions and CTEs, then logistic regression against XGBoost, reaching 0.777 AUC on a held-out set, with SHAP attributing each prediction to its features. The riskiest decile contains 31% of all defaults, a 3.1x lift over the base rate.

A grounded language-model layer drafts the weekly risk memo from the query output rather than from recall, so every sentence traces back to a number in the data.

What didn't work

I went looking for a strategy returning 50% a year. Four of the five routes I tried died the moment they met data they had not been fitted on, or prices that could actually have been traded. Keeping that record is more useful than deleting it.

Route Fitted on past data Held-out result Verdict
Weekly altcoin rotation 77–132% a year −3% a year from 2024 Dead
One-hour Donchian breakout Sharpe 4.36 Sharpe −0.89 Dead
4x leverage on the survivor — 12.3% a year at −63% drawdown Dead
Polymarket favourites 16 of 16 won 96% won at a 0.94 price, not significant Dead
Volatility-targeted momentum — Sharpe 1.08 at −15.6% drawdown Kept

The honest way to raise returns is not a cleverer signal. It is either accepting the roughly 1-to-1.5 return-to-drawdown arithmetic of trend following, or finding a structural mispricing and then being strict about whether the sample supports the claim and whether its prices could actually have been traded. Polymarket favourites looked like that kind of mispricing at sixteen wins from sixteen. Rerun on 587 markets, entering at the last real trade two weeks out, the apparent edge sat in stale prices: on fresh ones, favourites won 96% of the time against an average price of 0.94, an edge too small to tell from luck. The one candidate mispricing failed both tests.
